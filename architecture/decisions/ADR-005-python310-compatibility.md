# ADR-005: 支持 Python 3.10 并保留 Python 3.11 开发环境

- 编号：ADR-005
- 标题：最低支持版本降至 Python 3.10，标准开发环境继续使用 Python 3.11
- 日期：2026-09-04
- 状态：superseded（被 ADR-006 取代）
- 关联：Phase 0；ADR-003；`.github/workflows/test.yml`

## 背景

CAEGraph 的标准 Conda 开发环境固定为 Python 3.11，原有包元数据和 CI 也只接受
3.11，无法证明项目对仍被科学计算生态广泛使用的 Python 3.10 兼容。兼容性验证
不应要求贡献者创建第二个本地 Conda 环境，也不应降低标准开发环境版本。

ADR-004 已由并行的 Git 治理分支预留，因此本决策使用 ADR-005 编号。

## 决策

- `caegraph-dev` 继续以 Python 3.11 作为唯一标准开发环境。
- 包的最低 Python 版本改为 3.10，Black 与 Ruff 以 Python 3.10 语法为最低目标。
- CI 测试任务同时运行 Python 3.10 与 3.11；文档任务继续使用 3.11。
- 不为 3.10 创建新的本地 Conda 环境，也不为当前依赖增加不必要的上限。
- 只有 Python 3.10 与 3.11 的 CI 均通过，才能宣称兼容 Python 3.10。

## 备选方案

| 方案 | 结论 | 原因 |
| --- | --- | --- |
| 将唯一开发环境从 3.11 降为 3.10 | 否决 | 破坏既有环境约束，且不能同时验证 3.11 |
| 保持仅支持和测试 3.11 | 否决 | 无法满足 Python 3.10 兼容性目标 |
| 开发环境 3.11，CI 测试 3.10/3.11 | 采纳 | 扩大兼容性，同时避免本地多环境漂移 |

## 影响

- 公共 API 不变，但发布元数据允许 Python 3.10 安装。
- 新代码不得使用 Python 3.11 独有语法，除非未来通过 ADR 提高最低版本。
- 依赖解析必须在 Python 3.10 CI 中成功；若第三方最新版不支持 3.10，pip 应按
  `Requires-Python` 选择兼容版本，必要的版本边界必须走依赖变更工作流。
